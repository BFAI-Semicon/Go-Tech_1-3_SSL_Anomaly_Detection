## 3. 台帳の純粋ロジック

- [ ] 3.1 受け入れ検査と数値正規化を実装する
  - 登録は `accept_registration`、検索と類似度は `accept_query` を使う。検査順は、担保根拠と種別の整合 → 供給ラベルと申告種別の整合 → 抽出器同一性の全フィールド一致 → 埋め込み次元 → 数値契約 → L2 正規化に固定する
  - `accept_query` は埋め込みと抽出器同一性だけを受け取り、近傍数 `k` は受け取らない。`k >= 1` は検索クエリ型の構築時の不変条件とする
  - `acceptable` / `defect` は人手検証由来のみ。`normal` かつデータセット由来では供給ラベルが正常であることを要求し、人手検証由来では供給ラベルを拒否理由にしない
  - 空ストアへの初回登録で同一性メタを採用する。以後の不一致は項目をすべて列挙して拒否し、索引へは何も追加しない。検索時にストアが空なら同一性比較せず空結果側へ委ねる。非空ストアで検索・類似度の同一性が不一致なら、検索を実行せず全項目を列挙して同じ型付き例外で拒否する
  - 未提供メタは補完せず、split はパッチ特徴集合の供給値を採用値として載せる
  - 完了時: 担保根拠欠落・種別不整合・データセット由来×異常ラベル・次元不一致・複数項目の同一性不一致・非有限値・ゼロノルムが、状態を変えずに型付き例外または値エラーで拒否され、正規化後ノルムが 1 になる。`accept_query` が `k` を受け取らず、非空ストアでの検索・類似度の同一性不一致が検索未実行のまま全項目列挙で拒否されることがテストで確認できる
  - _Requirements:_ 1.7, 1.8, 2.1, 2.2, 2.3, 2.7, 4.5, 4.6, 6.4, 6.5
  - _Boundary:_ catalog.admission
  - _Depends:_ 2.3

- [ ] 3.2 集約判定と集約後レコードの合成を実装する
  - 最近傍距離がしきい値以内（等号を含む）なら集約し、同一の既存プロトタイプを最近傍とする複数クエリは 1 件へまとめる。要求内のパッチ同士は集約しない
  - 重心は寄与パッチ数で重み付けした平均の再正規化。由来ドメインは寄与の併合により和集合。間引き保護は論理和、失効期限はより遅い方（無期限を最も遅いものとして扱う）
  - 集約後レコードの合成は、呼び出し側から間引き保護と失効期限を受け取り、寄与（登録 ID と位置）からは読まない
  - 完了時: しきい値ちょうどで集約になり、同一近傍への複数クエリが 1 件にまとまり、保護が弱まらず失効期限が延びることがテストで確認できる
  - _Requirements:_ 1.4
  - _Boundary:_ catalog.merging
  - _Depends:_ 2.3

- [ ] 3.3 間引き対象の決定と上限の充足判定を実装する
  - coreset は間引き保護と欠陥種別を保護群にし、選択件数を上限から保護群件数を引いて求める。選択件数が負のときだけ充足不能とする
  - 選択件数 0 は充足可能（保護群だけを残す）。選択件数が選択可能群以上なら除外なし、0 なら選択可能群を全件除外対象にする、という区分を呼び出し側が判別できる形で返す
  - 失効間引きは、現在時刻を過ぎた生存プロトタイプのうち間引き保護を持たないものを返す。欠陥種別は coreset の保護群だが失効の対象からは外さない
  - 判定入力は保護・種別・失効期限・件数だけとし、補正レコードの参照有無を見ない
  - 完了時: 保護群が上限を超えると充足不能、保護群が上限と等しいと選択件数 0、欠陥種別が coreset 保護かつ失効対象、保護指定が失効対象外、になることがテストで確認できる
  - _Requirements:_ 5.1, 5.2, 5.3, 5.4, 5.7
  - _Boundary:_ catalog.pruning
  - _Depends:_ 2.3

- [ ] 3.4 プロトタイプ台帳の発番・生存状態・対応表を実装する
  - 識別子は発番済み最大値 + 1 の単調増加。発番済みレコードは削除しない。生存・集約による retire・間引き除外は相互排他
  - 登録計画と間引き計画は識別子を確定した差分だけを返し、台帳は適用操作で初めて変わる。適用は例外を送出しない
  - 解決は対応表を終端まで辿る。包含集合が生存の半数を超える識別子セレクタは除外セレクタへ切り替える
  - 完了時: 計画だけでは生存集合と対応表が変わらず適用後に反映されること、集約・間引き後に識別子が再利用されないこと、対応表の連鎖が終端まで解決されること、3 状態が相互排他であることがテストで確認できる
  - _Requirements:_ 1.5, 1.6, 3.3, 5.5, 5.6
  - _Boundary:_ catalog.registry
  - _Depends:_ 2.3

- [ ] 3.5 登録記録と間引き記録の追記・期間照会を実装する
  - 登録記録は登録時点の事実として追記のみし、その後の集約・間引きで書き換えない。実施日時は呼び出し側から受け取り、ジャーナルは時刻源を持たない
  - 登録記録に担保根拠、annotation メタ、構造化 JSON 参照、適用メタ、位置へ結ぶ登録 ID、ドメインタグ、由来キー、split を保持する。split はパッチ特徴集合の供給値の写しであり、担保根拠の split の権威は登録記録だけとする
  - 期間照会は登録記録と間引き記録を実施日時の昇順で返す。ドメイン／由来キー条件による登録 ID の絞り込みは 2.1 の一致規則を使う
  - 流出率・過検出率の算出は持たない
  - 完了時: 期間照会が昇順で両種の記録を返し、軸の無指定を含む絞り込みがテストで確認できる。率算出の関数や戻り値が存在しない。登録記録が split を保持する
  - _Requirements:_ 2.3, 2.4, 4.1, 4.2, 4.4, 4.5, 4.6, 8.1, 8.2, 8.3, 8.4
  - _Boundary:_ catalog.journal
  - _Depends:_ 2.3

- [ ] 3.6 評価用バンクの候補抽出と決定的サブサンプルを実装する
  - 候補は呼び出し側が渡した生存かつ欠陥以外のレコードに対し、包含由来キーに一致し、除外指定がある場合は除外由来キーを 1 つでも持つものを外して選ぶ。除外指定なしは除外判定を行わない
  - 候補識別子を昇順に並べ、指定シードの非復元抽出で固定サイズを取る。同一仕様・同一候補なら同一集合。不足時はバンクを作らず、バンク識別子・要求件数・利用可能件数を報告する
  - 構成は仕様・メンバー識別子・寄与パッチ数合計を保持し、同一バンク識別子の再構築は置き換えとする。指標算出は持たない
  - 完了時: 除外キーを持つ候補がメンバーから外れ、不足時に 3 属性付きで失敗し、同一シードで集合が一致し、パッチ数が寄与数合計になる。指標算出の関数が存在しない

## 5. 合成エンジン

- [ ] 5.1 登録・近傍検索・類似度照会・メタデータ照会を配線する
  - 合成ルートが台帳とベクトル索引の同期を担う。現在時刻は時計ポートから取得し、登録記録へ渡す。空の索引を前提に構築する
  - 登録は検査 → 同一種別の生存集合へのバッチ最近傍 → 集約計画 → 識別子確定 → 索引へ追加してから集約前を削除 → 台帳適用 → 記録追記の順。追加失敗時は台帳を変えず、削除失敗時は直前の追加を取り消してから失敗する
  - 集約合成には登録要求の `pinned` と `expires_at` を渡す。記録追記では採用した split を登録記録へ書く
  - 正常集合検索と識別子指定の類似度は、索引検索またはベクトル再構成の前に `accept_query` へ通す
  - 正常集合検索は、限定なしなら欠陥種別だけを除いた単一プール、ドメイン指定なら一致する生存識別子に限定し、常に欠陥種別を除く。識別子指定の類似度は種別を問わず生存のみを返し、集約済みは対応先を提示して読み替えず、未知／除外は未解決として残件は返す
  - 表示・識別子解決・ドメイン／由来キー絞り込み・期間照会は台帳と記録の合成に留め、メタ値の推測補完をしない。追記で集約されなかった識別子は追記前と同一の識別子で検索結果に残る
  - 完了時: 初期構築と追記が同一入口ででき、集約後識別子と対応表が返り、欠陥種別が正常集合検索から外れ類似度照会では返り、ドメイン限定の有無で対象が変わり、索引追加失敗時に生存集合・対応表・操作記録が要求前と一致する。非空ストアでの検索・類似度の同一性不一致が検索未実行のまま拒否されること、保護なし・失効 T1 の既存へ `pinned=True` とより遅い T2 を付けた集約後が `pinned=True` かつ T2 を持つこと、データセット由来登録の記録 `split` が供給値と一致することがテストで確認できる
  - _Requirements:_ 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 2.3, 2.4, 2.5, 2.6, 3.1, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8, 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 6.5, 8.1, 8.3
  - _Boundary:_ PatchFeatureStore.register, PatchFeatureStore.search_normal, PatchFeatureStore.similarities, PatchFeatureStore.describe, PatchFeatureStore.find_prototypes, PatchFeatureStore.resolve, PatchFeatureStore.operations, UtcClock
  - _Depends:_ 3.1, 3.2, 3.4, 3.5, 4.1

- [ ] 5.2 間引き・バンク・永続化を配線する
  - coreset 再選択は充足不能なら保護件数と上限を報告して状態を変えず、選択件数 0 なら選択器を呼ばずに選択可能群を除外し、生存が上限以内なら除外なし、それ以外だけ選択器を 1 回呼ぶ。間引き保護と欠陥種別は残し、除外識別子は再割当せず対応先も持たない
  - 失効間引きは時計の現在時刻を基準にする。間引き完了時だけ操作記録を残し、除外なしの経路では記録しない
  - バンク構築は寄与元の登録記録から由来キー集合を解決して渡し、複数バンクを保持する。検索でバンクとドメインが同時指定されたら交差だけを対象にし、交差が空なら空結果を返す。未構築バンクは識別子付きで拒否する
  - 保存はスナップショットを保存口へ渡す。復元は空の索引へ生存ベクトルを 1 回追加し、保存前と同一クエリが同一の識別子列と距離を返す
  - 合成ルートが 300 行を超える場合は、スナップショットの組み立てと復元だけを engine 層の第 2 段へ切り出し、層契約を更新する
  - 完了時: coreset の 4 分岐と保護対象の残留、失効除外、除外識別子の操作記録、除外由来キーを持つメンバーの不在、`exclude` なし構築での除外なし、永続化往復の同一検索結果、差し替え中断からの再読込がテストで確認できる
  - _Requirements:_ 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 6.1, 6.2, 6.3, 7.1, 7.2, 7.3, 7.6, 8.2
  - _Boundary:_ PatchFeatureStore.reselect_coreset, PatchFeatureStore.prune_expired, PatchFeatureStore.build_bank, PatchFeatureStore.bank_composition, PatchFeatureStore.save, PatchFeatureStore.restore
  - _Depends:_ 5.1, 3.3, 3.6, 4.2
