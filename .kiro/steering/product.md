# Product Overview

半導体製造向けの工程横断ゼロショット欠陥検出「Promptable Patch Retrieval」を開発する。
工程・材料・撮像条件が変わっても、案件ごとの教師あり再学習なしで欠陥候補を検出し、
人間フィードバックと構造化ルールで最終判定（NG／許容／要確認）へ収束させる。

権威ドキュメントは `docs/researches.md`。マルチ spec 分割と依存順は
`.kiro/steering/roadmap.md` を参照する。

## Core Capabilities

- **固定 SSL ViT によるパッチ特徴抽出** — DINOv3（anomalib）を主軸に重み更新せず特徴を得る。
  比較用バックボーンは設定切替
- **特徴量ストア＋一次異常検出** — 正常分布からの逸脱でヒートマップ／ROI 候補を出す
- **HITL → LLM 構造化** — ROI 注釈と自然言語を運用スキーマ JSON に落とす
- **補正レイヤ** — プロトタイプ近傍照合と適用条件で一次判定を再構成し最終判定する
- **評価基盤** — image-level／領域指標・特徴抽出器比較・運用 KPI を共通プロトコルで測る

## Target Use Cases

- 欠陥が稀でラベル付けコストが高く、工程・装置・材料をまたぐ汎化が必要な検査
- 正常メモリバンクとプロトタイプの追記だけでドリフトへ適応したい運用
- 過検出を許容／要確認へ落とすルールを、再学習なしで現場が蓄積したい運用

## Value Proposition

重み固定・推論時適応。勾配更新の代わりに、特徴ベクトルの追記と構造化フィードバックの
適用条件で運用側が適応する。判定の中核（補正レイヤのスキーマと優先順位）は自作し、
周辺（特徴抽出・ストア・LLM クライアント等）は採用ライブラリに寄せる。

## Development Shape

- 研究全体を 1 spec にしない。roadmap の依存順で機能単位に切る
- 実データ・実 LLM・実オントロジーは遅延し、合成 fixture で骨格を先に固める
- 複雑さは「補正レイヤ本体 → バージョン管理 → オントロジー」の順に 1 塊ずつ積む
  （`docs/incremental-development-plan.md`）
