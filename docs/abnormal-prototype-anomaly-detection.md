# 異常プロトタイプを利用した異常検知の研究調査

正常だけでなく異常（欠陥）サンプルをプロトタイプ／メモリバンクとして活用する研究があるか調査したメモ。本プロジェクトの `kind=defect` 設計との関係を整理する。

## 1. 異常メモリバンクを明示的に持つ手法（本プロジェクトの `kind` 設計に最も近い）

- **[DMAD: Dual Memory Bank for Real-World Anomaly Detection](https://arxiv.org/abs/2403.12362)**（2024）— 正常バンクと異常バンクの 2 つを持ち、クエリ特徴から両バンクへの距離・アテンションを計算して「正常からの距離＋既知異常への近さ」を統合した表現を作り、異常スコアを学習する。少数の注釈済み異常が手に入る現実の産業検査（semi-supervised・multi-class 統一設定）を明示的に想定しており、問題意識は本プロジェクトの `kind=defect` とほぼ同じ。ただしスコアリング部分は学習が必要。
- **[AnomalousPatchCore](https://arxiv.org/abs/2408.15113)**（ECCV 2024 Workshop）— PatchCore 系で異常サンプルを活用する研究だが、使い方が対照的。異常例は**特徴抽出器のファインチューニング**に使い、メモリバンク自体は正常のみのまま。「異常例は網羅的でなくとも特徴空間の分離を改善する」という知見を示す。凍結抽出器を前提とする本プロジェクトでは採れないアプローチだが、比較として有用。
- DSMBAD（2025）など「デュアルメモリバンク」を名乗る手法は他にもあるが、構造異常＋論理異常のような別軸の分割で、正常／異常の分割とは限らない点に注意が必要。

## 2. 少数のラベル付き異常を使う教師あり／Open-Set 系統（OSAD）

「検査で見つかった少数の欠陥例を活かしつつ、未知欠陥も検出する」という設定が **Open-Set Supervised Anomaly Detection** として確立している。

- **[DevNet](https://arxiv.org/abs/1911.08623)**（KDD 2019）— 少数異常で偏差学習。この分野の出発点。
- **[DRA](https://arxiv.org/abs/2203.14506)**（CVPR 2022）— 異常を「既知異常に似たもの・疑似異常・潜在残差異常」に分離して学習し、既知（gray swan）と未知（black swan）の両方を検出。
- **[PRN: Prototypical Residual Networks](https://arxiv.org/abs/2212.02031)**（CVPR 2023）— 正常パターンに対する**異常の残差をマルチスケールのプロトタイプ**として明示的に保持し、既知異常の拡張＋疑似異常生成で多様化。
- **[AHL](https://arxiv.org/abs/2310.12790)**（CVPR 2024）、**[DPDL](https://arxiv.org/abs/2502.20981)**（2025）— 少数異常例から異常分布の多様性（heterogeneity）をシミュレートして未知異常への汎化を高める、この系統の最新形。

この系統で一貫して報告される知見が 2 つある。

1. **既知異常の活用は主に過検出（FP）削減に効く**
2. **既知異常への過適合が未知異常の見逃しを招く**ため、どの手法も疑似異常生成や分布多様化でそれを緩和している

## 3. HITL フィードバックの逐次取り込み

- **[ICONP](https://arxiv.org/abs/2311.09004)**（2023）— 運用中に検査員の承認／棄却フィードバックを逐次取り込み、軽量な判定モジュールだけを更新して FPR を約 64% 削減。基盤モデルは変えずフィードバック層で適応する構図は、本プロジェクトの補正レイヤと同型。

## 本プロジェクトの設計への示唆

`kind` 設計（メタデータ層に `normal`／`acceptable`／`defect`、一次判定は `kind ∈ {normal, acceptable}` のみ、補正照合は全種別）は、この文献状況と整合的である。

- 「既知異常への類似を一次スコアへ直接加点しない」（構造化 JSON 設計メモ §2.1）という決定は、OSAD 系が一貫して警告する**既知異常への過適合→未知異常の見逃し**リスクを構造的に回避するもので、研究知見に裏付けられる。DMAD のように異常類似をスコアへ直接混ぜる手法は、その副作用を抑えるために学習（スコアリングネットワーク）を必要としている。
- 一方、**学習・微調整なし（凍結抽出器＋kNN のみ）で異常例を推論時参照に使う研究はほぼ空白**である。2025〜2026 年の training-free 系（HyperFSAD、SubspaceAD、DuoAD など）はいずれも正常参照のみ。つまり「`kind=defect` は一次判定に混ぜず、補正レイヤの `OverridePositive` 照合にのみ使う」という本設計は、既存研究の直接的な追試ではなく、DMAD 的な問題意識を training-free 制約下で保守的に実現する位置付けになる。research.md に先行研究として DMAD・PRN・DRA を引いておく価値はある。
