# 正常データのみの実機画像検証プラン

[VisA 検証ゲート](./visa-validation-gate.md) を通過した後、独自の半導体検査画像で行う最初の実データ検証。
実機データは**正常のみでラベルも画素マスクも無い**ため、検出性能ではなく
**過検出率・スコアの安定性・ドメインシフトの影響量・汚染候補**を測る検証として設計する。

## 測れること／測れないこと

先にこの線引きを固定する。ここが曖昧だと、測れないものを主張する結論になる。

### 測れること

- **過検出率（overkill rate）の実測**。全件が正常なので、フラグされた全件が過検出そのもの。
  `researches.md` §7 の運用 KPI を、欠陥ラベルなしで直接測れる。
- **スコアの安定性**。メモリバンクの構成を替えても同じ画像が高スコアになるか。
- **ドメインシフトの影響量**。工程・材料・装置を跨いだときの過検出率の増分。
  `researches.md` §8 の「撮像条件の変動が欠陥より支配的」というリスクに定量的な根拠を与える。
- **汚染候補の抽出**。正常と称するデータに混入した欠陥・異常撮像の洗い出し（§11 の汚染防止）。
- **必要な正常枚数の見積り**。バンクサイズと過検出率の関係。
- **特徴抽出モデルのドメイン不変性・安定性・データ効率の比較**。検出力ではなく、
  撮像条件の変動に対する鈍感さを比べる（S4）。

### 測れないこと（主張しない）

- image-level AUROC・AUPRO・PG2・F1-Max・AUPRC。異常が無いため TPR が定義できない。
- 流出率（escape rate）・見逃し。観測件数が原理的に 0 で推定できない。
- **特徴抽出モデルの検出力の優劣**。どのモデルが欠陥をよく見つけるかは VisA・MIIC で測る。
- **単一ドメイン内の過検出率によるモデル比較**。較正の仕方で値が決まるため自明化する（S4 参照）。
- 「安定している＝検出器として良い」という結論。理由は後述の読み方を参照。

これらは VisA と MIIC（画素マスクあり）で測る。役割を分けて、この検証に持ち込まない。

## 検証の設計

### 1. 分割は「複数バンク＋共通評価集合」にする

通常の K-fold（バンク = K-1 組、評価 = 残り 1 組）では、**各画像が評価側に 1 回しか登場しない**。
そのため「あるバンクでフラグされた画像が別のバンクでもフラグされるか」を照合できない。
2 組に分けて役割を入れ替えても、各画像が評価されるバンクは 1 つのままで解決しない。

同一画像を**それを含まない複数のバンク**に対してスコア化する構成にする。

- 最小構成: 互いに素なバンク A・B と、共通評価集合 C の 3 分割。C を A と B の両方に対して
  スコア化すれば、画像ごとに 2 つの判定が並ぶ。役割を回転させて全画像をカバーする。
- 一般形（推奨）: 固定サイズのバンクを B 個ランダムに作り、各画像を**それを含まない全バンク**に
  対して評価する。画像ごとに「B 個中いくつのバンクでフラグされたか」という**フラグ頻度**が得られる。

ペアごとの一致率より、フラグ頻度の分布を主に見る。0 と 1 に二峰化すれば「フラグされる画像は
バンク構成に依らず本質的に外れている」、中間に散らばれば「バンク構成の偶然でフラグが決まっている」と
そのまま読めるため、解釈が一意になる。

### 2. バンク・閾値較正・評価の 3 役を分離する

異常が無いので ROC で閾値を選べない。ここで「評価集合のスコア上位 q% をフラグ」とすると、
過検出率は定義上 q になり情報が消える。**バンクにも評価集合にも含めない較正用の正常サブセット**で
分位点から閾値を決め、それを評価集合に適用する。

閾値の与え方は 2 条件で比較し、不安定さの原因まで切り分ける。

- **絶対閾値を固定**: バンクを替えたときのスコアスケールのずれも含めて見る。運用に直結する厳しい条件。
- **バンクごとの分位点**: スケール差を正規化し、順位の一致だけを見る。

前者だけが崩れるなら再較正で対処できる問題、後者も崩れるなら本質的な不安定と判断する。

### 3. グループキーはウェハ・ロット・撮像日にする

同一ウェハの別ダイ・同一ロット・同一視野の連続撮像は近重複であり、バンク側と評価側に分かれて入ると
過検出率が楽観的に出る。分割の単位は画像ではなく**ウェハ ID／ロット ID／撮像日**にする。

### 4. 固定する条件と、振る条件を分ける

折数 K を振るとバンクサイズが連動して変わり、「K の効果」と「バンク枚数の効果」が交絡する。
**K は振らず、固定サイズのサブサンプルを B 個作る**設計にし、バンクサイズは独立の実験軸で振る。

固定して記録する条件は次の通り。

- バンクサイズ（枚数・パッチ数）、coreset 率、FAISS のインデックス方式
- kNN の k、スコア融合の重み、ドメイン分割の有無
- タイル化・パッチ化のサイズと重なり、バックボーン名・重みリビジョン・前処理条件（layer norm 等）

## 指標

- **過検出率**（主指標）。画像単位とパッチ単位を分けて報告する。
- **フラグ頻度分布**。画像ごとの「フラグされたバンク数 ÷ 評価されたバンク数」のヒストグラム。
- **フラグ集合の重なり**: Jaccard 係数と Cohen's κ。**生の一致率は使わない**
  （フラグ率 1% なら独立にランダムでも 98% 以上一致してしまい、情報がない）。
- **スコアの順位相関**: Spearman。閾値設計と独立に安定性を見られるため、最も頑健な診断値。
- **不確かさ**: bootstrap 信頼区間を全指標に付ける（`docs/plan.md` の k-fold ＋ bootstrap CI 方針）。

## 実験系列

### S1: ランダム分割（ノイズ床）

グループキーを守りつつドメインを混ぜてランダムに分割する。ここで測れるのは
バンクの標本ノイズだけであり、**以降の系列を読むための下限**として使う。それ自体は主張にしない。

### S2: ドメイン別グループ分割（本命）

装置 A の正常でバンクを作り、装置 B の正常を評価する。工程・材料でも同様に行う。
**S1 との過検出率の差分が、そのままドメインシフトの影響量**になる。
`researches.md` §7 の段階的ドメインシフト（同一工程→類似→異材料→異装置→異撮像）を、
正常データだけで描ける劣化曲線として実施する。欠陥ラベルが無い制約下で最も研究価値が高い系列。

### S3: バンクサイズ・coreset 率のスイープ

過検出率とフラグ頻度分布がどのバンク枚数で安定するかを見る。
「運用開始に必要な正常枚数」の定量根拠になり、`docs/plan.md` の計算資源検証にも接続する。

### S4: 特徴抽出モデルの比較

DINOv3（主軸）に対して DINOv2・DINO・ImageNet 教師あり CNN（`wide_resnet50_2`）を、
S1〜S3 と同じ分割・同じ条件で並べる。比較対象は `researches.md` §5 の新規性主張に対応する。

**まず、正常のみのデータで比較できない軸を確定させる。** 検出力（どのモデルが欠陥を見つけるか）は
測れない。さらに注意すべきことに、**単一ドメイン内の過検出率はモデルを識別しない**。
各モデルを較正集合の同一分位点に合わせれば、較正集合と評価集合が交換可能である限り、
評価集合の過検出率はどのモデルでもほぼその分位点の値になるからである。
「モデル A の過検出率が低い」という比較を単一ドメイン内でやっても、較正方法の副作用しか見ていない。

識別できるのは次の 4 軸で、いずれもラベルを必要としない。

- **ドメインシフト下の過検出率の増分**（S2 の差分をモデルごとに取る）。最重要の軸。
  同一ドメイン内で較正した閾値を別装置・別工程の正常に適用したとき、増分が小さいモデルほど
  撮像条件に鈍感で、工程横断で使える表現を持つ。**研究の核である工程横断汎化を、
  欠陥ラベルなしで定量比較できる唯一の軸**であり、この検証で最も価値が高い。
- **ドメイン間のスコア分布のずれ**。両者とも正常なので、ずれが小さいほど不変性が高い。
  2 標本間の距離（KS 統計量など）で測り、閾値の選び方に依存しない指標として上の増分を補強する。
- **安定性**。同一バンクサイズでの順位相関とフラグ頻度分布。正常の変動を少ないサンプルで
  覆えるモデルほど安定する。
- **データ効率**。S3 の曲線をモデルごとに描き、過検出率が安定するまでに必要な正常枚数を比べる。
  運用開始コストに直結する実務的な差になる。

副産物として、**汚染候補のクロス一致**が使える。複数モデルが一致してフラグする画像は
目視レビューの優先度が高い。逆に 1 モデルだけがフラグする画像は、そのモデル固有の
アーティファクトへの反応を疑う材料になる。

条件統一は VisA でのバックボーン比較と同じものを適用する（前処理条件、タイル化条件、k、
coreset 率、パッチ数基準でのバンクサイズ、距離尺度の正規化、抽出器同一性メタの添付。
詳細は [VisA 検証ゲート](./visa-validation-gate.md) のバックボーン比較の節）。

抽出器の最終選定は、この検証の 4 軸と、VisA・MIIC で測る検出力（AUROC／AUPRO）を
合わせて行う。どちらか一方だけでは決めない。

## 目視レビューと汚染候補の扱い

全バンクで一貫して高スコアになった画像を上位から目視レビューし、次に分類する。

- **真の欠陥**（正常と誤ってラベルされていた）→ メモリバンクに登録せず、
  `kind=defect` プロトタイプとして保持する（`researches.md` §11）。HITL の入力になる。
- **撮像アーティファクト**（フォーカス外れ・照明変動・搬送痕）→ 前処理・撮像条件側の課題として記録。
- **正常だが稀な外観** → バンクのカバレッジ不足。追記対象の候補。

この分類作業は、実データを HITL と補正レイヤへ流す最初の入口としても機能する。

## 結果の読み方

過検出率と安定性は**独立な 2 軸**であり、組み合わせで解釈する。

- **過検出率が低く、安定性が高い** — 良好。フラグは汚染候補として扱える。
- **過検出率が低く、安定性が低い** — 閾値付近のノイズが支配的。運用点が不安定で、
  較正方法かバンクサイズを見直す。
- **過検出率が高く、安定性が高い** — 系統的に同じものへ誤反応している。
  何に反応しているかを目視で特定するまで、他の数値を読まない。
- **過検出率が高く、安定性が低い** — バンクの正常カバレッジ不足。S3 で必要枚数を見積る。

**安定性が高いこと自体は良い結果ではない。** 常に同じものを誤検出する検出器でも安定性は最大になる。
極端な例として、スコアが画像の平均輝度にしか反応していなければ、どのバンクでも同じ画像が上位に来て
一致は完璧だが欠陥検出能力はゼロである。安定性は必ず**過検出率の絶対値**と
**フラグ画像の目視確認**とセットで読む。

## 完了条件

工程依存が大きいため過検出率の絶対基準は置かない。次が揃った時点で完了とする。

1. S1 の過検出率と bootstrap CI が、画像単位・パッチ単位で報告されている。
2. S2 の過検出率が S1 との差分として定量化され、ドメイン軸ごとに並んでいる。
3. フラグ上位が目視分類され、真の欠陥・撮像アーティファクト・稀な正常の内訳が出ている。
4. 固定条件（バンクサイズ・k・coreset 率・前処理・バックボーン）が記録され、再実行できる。
5. S1 のスコア順位相関が十分高い（目安 0.8）。下回る場合は配線とバンクサイズを先に疑う。
6. S4 のモデル比較表が、ドメインシフト増分・分布ずれ・安定性・データ効率の 4 軸で揃い、
   各行に抽出器同一性メタ（モデル名・重みリビジョン・前処理条件・埋め込み次元）が付いている。

## 所有と実装場所

- **分割プロトコルと指標**（過検出率・フラグ頻度・Jaccard・κ・Spearman・分布ずれ・bootstrap CI）
  および抽出器比較プロトコル: evaluation-framework。
- **グループキーのメタデータ**（ウェハ ID・ロット ID・装置・工程・材料・撮像日）と
  **バックボーン切替・前処理条件の統一・抽出器同一性メタ**: ssl-vit-feature-extraction。
- **バンクの構築・サブサンプル・coreset**: patch-feature-store。
- **スコア化と ROI 切り出し**: primary-anomaly-detection。
- **汚染候補のレビュー結果の受け取り**: llm-feedback-structuring、promptable-correction-layer。

## 着手前に確認すること

**グループキーのメタデータが実データに存在するかを最初に確認する。** ウェハ ID・ロット ID・装置・
工程・材料・撮像日・レシピが取得できなければ、S2（ドメイン別グループ分割）と近重複リークの
防止が成立せず、この検証は S1 と S3 だけに縮退する。ファイル名やディレクトリ構成から復元できるか、
別の管理システムから突き合わせられるかを、データ受領時に確認する。
